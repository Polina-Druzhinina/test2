# Task Tracker — автоматизация Python-проекта через Make

## Введение

В рамках данной работы был разработан консольный Python-проект Task Tracker и организован автоматизированный процесс разработки с использованием Makefile.

Основная цель проекта — показать, как Make может использоваться как единая точка входа для управления окружением, зависимостями и проверками качества кода.

В проекте реализованы:
- работа с виртуальным окружением
- автоматическая установка зависимостей
- запуск тестов
- статическая проверка типов
- проверка форматирования кода
- проверка зависимостей проекта

Все действия автоматизированы через Makefile, что позволяет воспроизводить процесс разработки и проверки проекта на любой машине без ручной настройки окружения.

## Последовательность действий без Make

До автоматизации через Makefile работа с проектом выполнялась вручную.

### 1. Создание виртуального окружения
```
python -m venv .venv
```

### 2. Установка зависимостей
```
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

### 3. Запуск приложения
```
.venv/Scripts/python.exe src/main.py
```
### 4. Првоерка типов
```
.venv/Scripts/python.exe -m mypy src tests
```

### 5. Проверка стиля
```
.venv/Scripts/python.exe -m black src tests scripts
```

### 6. Запуск тестов
```
.venv/Scripts/python.exe -m pytest
```

### 7. Проверка зависимостей
```
.venv/Scripts/python.exe scripts/check_requirements.py
```

## Описание предложенного решения

Основной задачей проекта было построение воспроизводимого процесса разработки Python-приложения с использованием Makefile.

В качестве демонстрационного приложения был реализован консольный Task Tracker, позволяющий:
- добавлять задачи
- просматривать список задач
- отмечать задачи как выполненные

Главный акцент сделан не на сложности приложения, а на организации процесса разработки и автоматизации типовых действий.


## Работа с виртуальным окружением

Проект использует локальное виртуальное окружение `.venv`.

Все команды запускаются через явный путь к интерпретатору: `.venv/Scripts/python.exe`

Такой подход был выбран вместо ручной активации окружения через `activate`, поскольку Make выполняет каждую строку target отдельно и не сохраняет состояние shell между командами.

Использование явного пути гарантирует:
- воспроизводимость окружения
- независимость от системного Python
- корректную установку зависимостей
- одинаковое поведение команд на разных машинах

## Проверка зависимостей

В проекте реализована автоматическая проверка зависимостей через скрипт: `scripts check_requirements.py`

Скрипт:
- анализирует импорты в исходном коде
- сравнивает их с `requirements.txt`
- сообщает об отсутствующих зависимостях

Это позволяет поддерживать соответствие между кодом проекта и его окружением.

## Проверка типов

Для статической проверки типов используется MyPy.

Проверка запускается командой: `make typecheck`

Статический анализ позволяет находить ошибки типов до выполнения программы и делает код более предсказуемым и безопасным.

## Проверка стиля кода

Для форматирования и проверки стиля используется Black.

В проекте разделены:
- автоматическое форматирование (`make format`)
- проверка форматирования (`make check`)

Это позволяет поддерживать единый стиль кода во всём проекте.

## Тестирование

Для автоматического тестирования используется PyTest.

Тесты расположены в директории: `tests/`

Тестирование позволяет автоматически проверять корректность работы основных компонентов приложения.

## Структура проекта

### `src/`
Основной исходный код приложения.

### `tests/`
Автоматические тесты проекта.

### `scripts/`
Вспомогательные скрипты проекта.

### `Makefile`
Централизованная автоматизация всех процессов разработки.

## Makefile как единая точка входа

Makefile объединяет:
- установку зависимостей
- запуск приложения
- тестирование
- проверку типов
- проверку зависимостей
- форматирование кода

в единый воспроизводимый workflow.

Главный target:

```
check: lint typecheck test check-requirements
```

Таким образом одна команда запускает полный цикл проверки проекта.
